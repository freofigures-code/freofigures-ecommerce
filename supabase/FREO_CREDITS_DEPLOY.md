# Implantação dos Créditos Freo

O fluxo `criar-pagamento` do n8n permanece igual. O checkout envia `total_com_frete` já com o desconto. O pagamento é conferido em uma função Supabase independente usando o ID, o valor aprovado e `metadata.user_id` que o workflow atual já envia ao Mercado Pago.

1. Revogue a credencial do Mercado Pago exposta no JSON compartilhado e gere outra. Atualize a credencial no n8n. Guarde a nova também como segredo `MERCADOPAGO_ACCESS_TOKEN` das Edge Functions no projeto Supabase. Nunca coloque o token em SQL, no frontend ou no Git.
2. Publique as funções `freo-checkout` e `freo-payment-sync` neste projeto. `supabase/config.toml` exige JWT para a primeira e desativa a checagem de JWT para a segunda, que é chamada pelo banco; ela não confirma nada sem consultar e conferir o pagamento no Mercado Pago.
3. Execute **uma vez** [202609300002_freo_credits.sql](migrations/202609300002_freo_credits.sql) no SQL Editor do projeto `rrmxqpvxrpcqqxsgccqw`, depois da migração `202609300001_guard_generation_pricing.sql` que já foi confirmada. O script é transacional e para sem aplicar mudanças se a estrutura verificada de `orders`, `generation_jobs`, `pg_net` ou `pg_cron` não existir.
4. Execute [freo_credits_postflight.sql](diagnostics/freo_credits_postflight.sql). Todos os campos de `verificacao_creditos_freo` devem retornar `true`.
5. Publique o frontend desta revisão. Teste com uma conta cadastrada: geração por texto e por imagem (10 créditos cada), compra parcial, compra 100% em créditos, pagamento aprovado e pagamento recusado. O usuário anônimo pode continuar comprando como convidado, mas não recebe o bônus de cadastro nem utiliza créditos.

Cada conta cadastrada existente e nova recebe 50 créditos uma única vez. Gerações anteriores não são cobradas; compras anteriores à migração não recebem recompensa retroativa. Cada R$ 1 **efetivamente pago** em novo pedido confirmado rende 1 crédito inteiro, arredondado para baixo; a parcela coberta com créditos não gera novos créditos. Em pedidos integralmente cobertos, o servidor recalcula produtos, kit, cupom e frete e conclui o pedido com pagamento de R$ 0,00 sem chamar o Mercado Pago.

A reserva de créditos para uma compra parcial ocorre antes da chamada ao n8n. Se o Mercado Pago confirmar recusa/cancelamento, a função devolve os créditos uma vez. Pedidos ainda pendentes com ID do Mercado Pago são conferidos a cada hora. Se houver falha de rede sem ID de pagamento confirmado, a reserva permanece até reconciliação segura; não a devolva apenas porque o navegador falhou, pois o pagamento pode ter sido criado. Os pedidos pagos pelo webhook n8n são conferidos pela função Supabase; `pg_net` dispara a conferência e `pg_cron` tenta novamente a cada cinco minutos quando houver falha transitória.
